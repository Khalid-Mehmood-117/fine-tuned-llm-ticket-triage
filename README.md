# fine-tuned-llm-ticket-triage

Small open-source LLM (Qwen2.5-0.5B-Instruct) fine-tuned with LoRA to turn a customer support
ticket into a strict JSON triage decision: category, priority, sentiment, needs_human, suggested
action and a short reason. Deterministic business rules run in code after the model, so safety,
legal and security calls never depend on the model alone. Compared against the base model and
gpt-4o-mini on a held-out test set.

> **Work in progress.** Milestone 1 (dataset) is done. Training, evaluation and the demo follow.
> See [PLAN.md](PLAN.md).

## Data
**The dataset is fully synthetic.** All 1,680 tickets were generated by gpt-4o-mini from sampled
label specs across six fictional companies, nine writing styles and six languages. No real
customer data is used. A human reviewer checked 50 test labels and confirmed 41 of 50 (82%);
the 9 corrections are applied. Details, counts and the hand check are in the
[data card](data/DATA_CARD.md).

**Bias note:** gpt-4o-mini wrote the tickets, so its phrasing is built into the data. This may
favour gpt-4o-mini in the comparison with the fine-tuned model. Labels are sampled before the
ticket is written (never guessed by gpt-4o-mini) and 50 test labels are hand checked, which
reduces this bias but does not remove it.

## Output schema
```json
{"category": "refund", "priority": "high", "sentiment": "negative", "needs_human": true,
 "suggested_action": "start_refund_review", "reason": "Charged twice for one order and wants the duplicate back."}
```
Fixed label sets are defined in [src/triage/schema.py](src/triage/schema.py) and explained in
[src/triage/labels.md](src/triage/labels.md).
